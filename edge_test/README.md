# edge_test

The folder that goes to the device. Copy the whole thing; nothing outside it is needed there.

Four tracked files - `run_inference.py` (what the device runs), `pack.py` and `report.py` (what
the host runs), and this. Everything else in here is generated by `pack.py` and gitignored:
`weights.pt`, `waveforms/`, `manifest.json`, and copies of the `phase/` and `models/` modules that
decide the numerics.

## The loop

```bash
# 0. what is on the device? read-only, installs nothing
poetry run python -m edge_test.pack --probe <ip>

# 1. fill this folder from a checkpoint
poetry run python -m edge_test.pack --checkpoint outputs/<date>/<time>/fold_0/checkpoints/best-epoch=NN.ckpt

# 2. copy the folder over (Cyberduck, or scp) and run it there
scp -r edge_test root@<ip>:/data/edge_test
ssh root@<ip> 'cd /data/edge_test && /opt/env/bin/python run_inference.py --runs 10'

# 3. bring the whole run back - figures included, they were drawn there
scp -r root@<ip>:<folder on the device>/out edge_test/
```

The device needs python 3.12 with numpy and torch. `holosissystem` installs both, into `/opt/env`
(or `/data/env` on the older layout) - `--probe` says which.

## Where things land

**The figures are drawn on the device, by the run.** matplotlib and pandas are `holosissystem`
dependencies, so `run_inference.py` draws its own plot the moment it has the numbers - no copy back
needed to see it. If they turn out to be missing it says so and the run's data is still complete,
ready to be drawn anywhere else with `report.py`. `--no-figures` writes the data only.

Everything a run produces is under `out/`, inside this folder, on whichever machine ran it:

| what | where |
|---|---|
| the payload | `edge_test/` itself |
| the run | `out/` - `results.json`, `timings.csv`, `predictions.npz`, `manifest.json` |
| **the plot**, the table, the prediction pages | `out/report/<the run's stamp>/` - one directory per run, with a copy of the run in it |
| every run, one row | `out/report/index.csv` |

So the round trip is one recursive copy of `out/`, and it brings the figures with it. `report.py`
re-draws a run kept anywhere else with `--from <dir>`.

**`pack.py` deletes `out/` when it re-packs.** That is what stops a report made here from being
copied to a device and read there as the device's own output - so re-pack before you copy the folder
over, and copy a device's `out/` off before you re-pack.

The manifest travels with the run, so a returned run names its own checkpoint, dataset and decoding
table.

## What it measures

**Correctness.** `pack.py` records the host's own logits beside every waveform, and the device has
to reproduce them - on every run, so nondeterminism cannot hide behind the first one. A wrong BLAS,
a truncated file or a different torch shows up as a logit difference rather than as a slightly
worse F1 nobody can interpret. Exit status is 0 only if every window matches inside
`run_inference.py: LOGIT_TOLERANCE` **and** decodes to the same labels.

**Latency.** One pass says nothing, so `--runs N` walks the whole set N times and keeps every
measurement; `--warmup N` discards the passes where torch is still allocating.

Windows come from the **held-out** split of the dataset the checkpoint trained on, read from the
`dataset.txt` that `train.py` writes beside every fold - never training data. Two filters, both on
by default: one duration only (`--seconds 20`, because the net is convolutional and a longer window
just costs more), and no windows the reference left entirely unknown (`--all-unknown` keeps them,
but they score 1.00 or near zero on the single class in play).

## What comes out

| file | what it is |
|---|---|
| `results.json` | pass/fail, latency percentiles, per-window scores |
| `timings.csv` | one row per window per run - the distribution itself, nothing aggregated |
| `predictions.npz` | the labels the device decoded, beside the reference |
| `latency.png` | histogram of the **net forward alone** over the bulk, the tail as one counted bar past a break, every measurement as a rug, and the median against the window's own duration |
| `latency_summary.csv` | per window: net mean / sd / min / p50 / p95 / max, and what the decoder adds |
| `predictions_page_*.png` | the device's labels against the reference, worst first |

The last three land in `out/edge_reports/<stamp>/`, together with a copy of the four files above -
so one directory is one run's whole story and can be archived or attached to a ticket on its own.

### One run does overwrite another, on the device

`results.json`, `timings.csv` and `predictions.npz` are written to the folder root there, so a
second run replaces the first - it says so, naming the run it is replacing, before it starts. Copy
them off before running again. On the host nothing is overwritten: each run gets its own stamped
directory under `out/edge_reports/`.

`forward_ms` is the network alone - normalisation plus the forward pass. `decode_ms` is Viterbi
(and the minimum-duration pass, where the checkpoint was trained with it on). The decoder is a few
percent of the forward pass, so the figure plots the net and states what the decoder costs;
`report.py --with-decode` plots the sum instead.
